## Findings ledger

### RBF-004 — Confidentiality not enforced by sampled policy design
**High · confirmed static design defect.** The UI promises: “Responses are fully confidential and used only in aggregate to guide product direction.” ([`FeedbackFlow.tsx:53–60`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/pages/FeedbackFlow.tsx#L53-L60)). The sole migration in the complete snapshot tree enables RLS, but for each of `feedback_sessions`, `feedback_answers` and `feedback_summary` uses `FOR SELECT USING (true)`, `FOR UPDATE USING (true)` and `FOR INSERT WITH CHECK (true)`, without role or ownership predicates: [sessions](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/supabase/migrations/20260311125937_605e594f-10de-4f2e-9eb3-e63f070d72db.sql#L17-L26), [answers](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/supabase/migrations/20260311125937_605e594f-10de-4f2e-9eb3-e63f070d72db.sql#L28-L49), [summary](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/supabase/migrations/20260311125937_605e594f-10de-4f2e-9eb3-e63f070d72db.sql#L51-L74).

For roles with corresponding table/API privileges, those predicates do not prevent cross-session reads or tampering. No deployed migration, grants, public/anonymous access, breach or actual exposure was established. Before release, the owner must approve a concrete access model, inspect effective grants/policies and validate isolation; align consent, retention and confidentiality copy with observed practice. See RBF-T2.

### RBF-005 — Persistence failure can appear to complete
**Medium · confirmed static error-handling gap; impact unmeasured.** Creation checks `error`, but the catch returns a random local session ([`useFeedbackSession.ts:10–30`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/hooks/useFeedbackSession.ts#L10-L30)); the page advances when `if (newSession)` ([`FeedbackFlow.tsx:199–210`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/pages/FeedbackFlow.tsx#L199-L210)). `saveAnswer` and `saveSummary` await operations without inspecting returned errors; thrown exceptions are logged and swallowed ([`useFeedbackSession.ts:33–59`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/hooks/useFeedbackSession.ts#L33-L59), [`:78–98`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/hooks/useFeedbackSession.ts#L78-L98)). The completion handler then calls `setStage('report')` ([`FeedbackFlow.tsx:229–236`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/pages/FeedbackFlow.tsx#L229-L236)). Respondents could believe submission succeeded when persistence failed; no failure or data loss was observed at runtime. Expose truthful status and test distinct returned and thrown failures, including retry and completion (RBF-T3).

### RBF-001 — Sampled CI workflow omits lint and tests
**Medium · confirmed static.** The manifest defines `"lint": "eslint ."` and `"test": "vitest run"` ([`package.json:6–13`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/package.json#L6-L13)); the [workflow](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/.github/workflows/ci.yml#L1-L18) runs `bun install --frozen-lockfile` and `bun run build`, not those checks. This workflow alone does not gate lint/test regressions; branch protection, other merge rules and actual merge outcomes are unknown. Add and validate meaningful gates (RBF-T4).

- **Correctness:** the questionnaire calculates reports locally; fallback and swallowed errors undermine confirmation of persistence (RBF-005). Chapter validation, scoring correctness and `updateSession` usage remain unverified.
- **Automation/testing:** RBF-001/002 are bounded to the sampled workflow and test. The complete tree lists one matching `src` test/spec file and Playwright configuration, whose contents were not inspected. No coverage percentage or green test run is claimed.
- **Operations:** [README deployment guidance](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/README.md#L63-L73) contains a placeholder project URL; actual hosting, database ownership, monitoring, backup, recovery and release state are unknown. Historical Actions metadata reports [one successful CI run](https://github.com/knarayanareddy/rocketboardfeedback/actions/runs/36902712400) at this exact SHA; logs were not inspected, and success proves neither tests nor current health.
- **Security:** authentication and effective authorization are unknown; RBF-004 identifies permissive source policies, not confirmed deployed privileges. Chapter input validation, injection handling and output rendering need review. The tree contains `.env`, but contents were not inspected and its existence proves no secret. The workflow uses `bun-version: latest` and major action tags ([lines 13–18](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/.github/workflows/ci.yml#L13-L18)); `bun.lock`, `bun.lockb` and `package-lock.json` coexist in inventory. Authority and integrity are unknown, not evidence of compromise, inconsistency or a CVE.
- **UX/accessibility:** [`FeedbackFlow.tsx:74–136`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/pages/FeedbackFlow.tsx#L74-L136) offers two modes and [`:276–313`](https://github.com/knarayanareddy/rocketboardfeedback/blob/3b01e5fa5046ec139102e518c69b13ba8055ce6a/src/pages/FeedbackFlow.tsx#L276-L313) provides navigation. ## Owner decisions and release blockers

Before production, identify the Supabase project, actual grants, hosting/release owner, intended anonymous or authenticated participation, access to individual responses versus aggregates, data minimization, consent, retention and restore targets. Approve a safe access design and evidence of persistence, accessibility, security and recovery. The root route is already known; whether another shell or `Index.tsx` is intended is a separate question. The owner authorized this defensive documentation campaign and draft PRs, as recorded in `fleet-hardening-review/PUBLICATION_AUTHORIZATION.md`; no new per-finding consent is required. Before publication, exclude real credentials, personal data and operational exploit payloads, and privately hold genuinely restricted additional evidence. Publication does not imply RBF-004 is fixed or deployed access is verified.
